# Artifact writer admission

Git's index can retain differently cased project paths even when a checkout
materializes one directory. Exact spelling claims prevent new aliases; safe
historical repair also needs admitted writers to finish before moving a bucket.

## Writer contract

A cooperative writer acquires a project lease before reading state used in a
mutation, and holds it through the final write, close and asynchronous settlement.
Shell/Bun command wrappers retain a lease over the complete command; libraries
retain it over the complete operation. Nested asynchronous operations retain their
own reference. A native child started by an admitted holder can acquire a separate
child lease while a window drains; the child remains visible if its parent exits.
A new skill workflow cannot inherit that exception. Direct agent report writes
are covered by the persistent skill-start lease until skill-end.

Metadata is outside `projects/<slug>`, keyed by Unicode NFC plus casefold. A held
project remains closed to new writers while another project stays writable.
`gstack-artifact-window.py begin ROOT SLUG --seconds 300` creates a pending
window. `status ROOT SLUG --id ID` reports existing writers; `assert` succeeds
only when none remain and the deadline has not expired. `end` explicitly releases
the owned window. The maximum duration is 900 seconds. Expiry does not reopen it.
Do not infer completion from age, a missing PID, a timeout, or one idle probe.
Unknown/dead owners, damaged metadata, unresolved destination links and ambiguous
ownership refuse rather than being automatically removed.

An interrupted command holder retains its lease if its direct child is still
alive. Whole-command wrappers require children either to finish within that
command or to participate independently; direct child exit is not process-tree
containment. This cooperative protocol is not an OS security boundary.

## Operational qualification

The maintenance-window implementation is qualified only on POSIX. Windows
ordinary writer liveness uses a SYNCHRONIZE-only process handle and a zero-time
wait, not `os.kill(pid, 0)`; actual Windows execution remains a CI qualification.
The Windows maintenance entry explicitly refuses. Its refusal test stays active;
POSIX maintenance tests are platform-scoped rather than asserting unsupported
Windows behavior.

Before historical repair, deploy the same writer-aware build to all participating
publishers and drain older agent sessions and daemons. Any unknown or nonparticipating
writer is a blocker. Then close project admission, drain existing leases, and take
the root Git lock for the exact index/HEAD/remote-CAS transaction, in that order.
The scope window alone does not authorize Git repair or establish GBrain source
ownership. Use the native GBrain owner/topology/drain fence, preview-bound byte
and index checks, durable recovery receipt and independent readback as well.
Do not delete old data, reset an index, change warning thresholds, or claim
production recovery from these synthetic tests.

## Failed publication

A refused image destination keeps already-generated bytes in the existing recovery
copy path. Publish those bytes once after resolving the hold; do not call the model
again. Evidence logging preserves the child result after dispatch; a project hold
is a pre-dispatch refusal. An impossible state root with a non-directory ancestor
skips bookkeeping and still runs the command, preserving the existing transparency
contract without attempting a project mutation under that impossible root.
